# ADR-0011：时间线改为构建期解析 git 日志

## 状态

已实施

## 背景

`/timeline/` 的事件原为手写 front matter，末条停更后长期无人登记。
手写台账在现有提交频率下不可维护——不是「暂时没更新」，是没有机制强制更新。

## 决策

事件改由构建期解析 `git log` 生成。

口径（拍板）：**除维护类前缀（`docs` / `chore` / `style` / `test`）之外全部算事件**。
不用「`feat:` 才算」：功能变化也可能以 `refactor(...)` 提交（如提示块语法收敛），
按 feat 白名单会漏掉。放宽后仍滤掉 docs/chore/style/test 噪音。

## 后果

- 时间线随每次构建自动更新，不再依赖人工登记
- 事件措辞是开发视角（提交信息写给开发者），与访客视角存在错位；这是自动化的固有代价
- **口径注记：计数与 HEAD 绑定，不是固定值。** 事件数、跨天数、顶层条目数都随提交单调增长，
  即便用的是同一个 HEAD。故任何「N 个提交 → M 条事件」的绝对数字复验都会得到不同结果；
  **验收只锚定提交与渲染形态（同日分组生效、单日多条走 `.timeline-subitems` 子列表），不用绝对数字**
- `renderPageTimeline` 因此新增同日分组行为，单日多条的详细项收进 `.timeline-subitems` 子列表。
  单日单条的输出逐字节不变，兜底快照的渲染结果零变化
- 数据源依赖构建环境有完整 git 历史，要求是 HEAD 处能追到现有时间线起点（`2026-07-30`）之前。
  **提交数随开发增长，此处不构成判据**；浅克隆的判别见
  [WORKFLOW.md → 发布与验证](../WORKFLOW.md#发布与验证)
- 兜底：浅克隆或无 git 时回退到 front matter 的手写快照，页面不会变空
- 构建命令必须保证完整 git 历史（含浅克隆判据的幂等写法）。写法与反例见
  [WORKFLOW.md → 构建前置](../WORKFLOW.md#构建前置构建环境必须有完整-git-历史)，
  不要在此复制一份，免得两处各自漂移
