# ADR-0012：展柜三页收敛与导航重构

## 状态

已实施

## 背景

「展柜」二级菜单下有四个子项：项目 `/projects/`、技能 `/skills/`、时间线 `/timeline/`、相册 `/gallery/`。
三者各有问题：

- 相册页六张「示例照片一…六」全部指向首页随机封面池的 `cover-01.jpg`…`cover-06.jpg`，
  与文章的无封面随机图同源。页面不是相册，是封面池再展一次
- 技能页六条技能与关于页第一段自述、`/projects/` 每条的 `lang` 字段三处复述，独立布局 16 行 + 独立导航子项
- 项目页 7 条与关于页「做过什么」2 条重复，且同一项目在两处链到不同目标
  （关于页 BiliCompact 指 Greasy Fork，项目页指 GitHub）

## 决策

- 删除 `/gallery/`、`/skills/`、`/projects/` 三页与对应布局 `gallery.ejs`、`skills.ejs`、`projects.ejs`
- 作品集（7 项）与技能（6 条）并入关于页；作品列表用 `:::fold[details]` **默认折叠**，避免关于页过长
- 取消「展柜」导航层级（四个子项删三个，父项 url 指向被删页面），「时间线」移入「关于」子菜单
- `/projects/` 旧 URL 301 到 `/about/`（内容搬移，不是内容消失，与「已删文章允许 404」的先例不同）

## 后果

- 关于页成为「作品 + 技能 + 自述 + 联系方式」的聚合页，作品列表默认折叠以控制长度
- 作品列表的最终形态是**每个项目一条规范链接**：7 条各自指向对应的 GitHub 仓库，
  仅 BiliCompact 在 GitHub 链接之后另附 Greasy Fork 安装入口（唯一的功能性第二链接）。
  「同一项目在两处链到不同目标」的分叉（关于页与 `/projects/` 各维护一份作品清单）
  随收敛为单页而不复存在
- `/projects/` 的 `pinned` 置顶能力消失（拍板时已知代价）
- 顶栏一级项从 6 个变为 5 个：首页 / 分类 / 搜索 / 关于 / 设置
- 三页已登记进 `docs/EXCLUDED.md`，防止日后被当缺口补回来
