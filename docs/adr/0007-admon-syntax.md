# 0007: 提示块语法收敛为 :::admon[...]

日期: 2026-08-25

## 背景

提示块原本有五种容器头（`:::note` / `:::tip` / `:::important` / `:::warning` /
`:::caution`），自定义标题用 `:::类型[标题]`。语法家族五种拼法，读者要记五个词；
`:::tip[标题]` 这种"类型+括号标题"还与其他扩展的"方括号包首参"惯例（`:::fold[...]`、
`::card{...}` 语义不同但位置一致）不一致。

## 决策

收敛为单一容器头 `:::admon[类型 可选标题]`：

- 类型移到方括号内首词（不区分大小写），其余文本 trim 后作标题——参数解析模式
  与 `:::fold[mode label]` 完全同构。
- 方括号可整体省略：`:::admon` 等价于 `:::admon[note]`（与 CSS 兜底
  `--admonitions-color-note` 的默认值一致）。
- 首词非类型时宽容兜底：`note` + 全串作标题（如 `:::admon[注意]` → note +
  标题「注意」），与 fold 的 mode 兜底先例一致；写错标题意图时不至于整块失效。
- 产物 HTML（类名、data-callout、bdm-title 结构）逐字节不变，样式零改动。
- 旧五种写法（`:::note` 等）不再匹配，按普通文本原样输出（写错时显眼暴露）。

## 理由

- 一个容器头一个家族，与卡片（`::card`）、折叠（`:::fold`）的"单指令+参数"
  心智统一。
- 宽容兜底让"只想写标题"（`:::admon[注意]`）与"忘记类型"都不炸块。
- 产物不变意味着零样式风险；语法迁移即正则与 parseAdmonMeta 的纯函数替换，
  有单测与构建产物 diff 双重验证。

## 影响

- 正文 9 处一次性迁移（`:::note` 等 → `:::admon[...]`），样板文同步更新。
- 语法唯一事实源 GRAMMAR.md；实现 THEME.md；ADR 记本决策。
