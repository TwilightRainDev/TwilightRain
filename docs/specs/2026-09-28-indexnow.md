# 规格：IndexNow 提交（独立 CI）

> 来源：`docs/BACKLOG.md`「IndexNow 提交」；密钥归属见 ADR-0009。
> 与本轮 B（已发布文章注记）并行。C（时间线兜底）由另一代理改另一组文件，本规格不碰 `source/timeline/`。

## 1. 要解决什么

密钥文件已在站点根，搜索引擎可以验证所有权，但没有任何提交机制。新 URL 只能等爬虫自己来。

本轮补上提交：构建完成后（或定时），把线上 sitemap 里的 URL 发给 IndexNow。**不**把这一步接进 `npm run build`。

## 2. 范围

| 做 | 不做 |
|---|---|
| Node 脚本读线上 sitemap，POST 到 IndexNow | 改 Hexo 构建链路、`after_generate`、`package.json` 的 `build` 脚本 |
| GitHub Actions：push `main`、每日定时、手动触发 | Cloudflare Worker / Pages 构建步骤 |
| 密钥仍用现有 `7facecda-3b42-4e79-ac12-ccddb9a0270e.txt` | 换密钥、把密钥放进 GitHub Secrets（密钥按协议必须公开） |
| 提交 `https://twilightrain.com` 的 URL | 提交 `twilightrain.pages.dev`、`/egg/`（sitemap 本来就没有） |
| 单测锁：payload 形态、sitemap 解析、`build` 不含 indexnow | 真打 IndexNow 端点的集成测试 |

## 3. 行为

- **脚本**：`scripts/indexnow-submit.js`。无额外 npm 依赖，用 Node 20 内置 `fetch`。
- **URL 来源**：`GET https://twilightrain.com/sitemap.xml`，抽出 `<loc>`。只保留 host 为 `twilightrain.com` 的 `https` URL。拉线上产物，避免提交尚未部署的地址。
- **等待**：GitHub Action 在 `push` 到 `main` 时先等 180 秒再拉 sitemap（Cloudflare Pages 约 1–2 分钟）。定时任务与 `workflow_dispatch` 不等。
- **POST**：`https://api.indexnow.org/indexnow`，`Content-Type: application/json; charset=utf-8`。body：

  ```json
  {
    "host": "twilightrain.com",
    "key": "<密钥文件正文>",
    "keyLocation": "https://twilightrain.com/7facecda-3b42-4e79-ac12-ccddb9a0270e.txt",
    "urlList": ["https://twilightrain.com/...", "..."]
  }
  ```

- **成功**：HTTP 200 或 202。其它状态码或网络失败：非零退出。
- **空列表**：sitemap 解析后 0 条 URL，非零退出（说明拉错或站点异常，不要静默成功）。
- **上限**：单次最多 10000 条（协议上限）。本站远低于此；超过则非零退出，不要截断。
- **本地**：`npm run indexnow` 只跑该脚本，不先 `hexo generate`。`--dry-run` 打印条数与 payload，不 POST。
- **密钥读取**：默认读仓库内 `source/7facecda-3b42-4e79-ac12-ccddb9a0270e.txt`（trim 后须与文件名 UUID 一致）。

## 4. 完成判据

1. `package.json` 的 `scripts.build` 字符串不含 `indexnow`。
2. `npm test` 含本轮单测且全绿。
3. `docs/adr/0017-indexnow-submit.md` 已写；0009 指向 0017；BACKLOG 该条改为已落地。
4. `.github/workflows/indexnow.yml` 存在，且不在 Hexo 构建命令里出现。
