BiliCompact 是一个用来精简 B 站首页的浏览器用户脚本。

它能限制视频显示数量，过滤直播、广告、番剧和付费课程，也可以清理评论区里的一些不想看到的内容。

这个东西最初只是为了自己用。后来觉得可能也有人有同样的需求，就整理了一下，放到了 GreasyFork 和 GitHub 上。

这篇文章主要介绍它能做什么、怎么安装，以及开发过程中用到的一些方法。完整源码也一并公开，感兴趣的话可以自己研究或修改。

> 以下为 BiliCompact 用户脚本 v2.6.0 的源码与项目介绍，采用 MIT 协议，可自由使用、修改和分发。

## 二、为什么会有这个脚本

事情很简单。

写了一天代码，晚上想打开 B 站看两个视频放松一下。

首页一刷新，直播、番剧、推广、付费课程，各种推荐内容挤在一起。

这些内容本身没什么问题。喜欢看直播的人可以看直播，追番的人也有自己的需求。

对我来说，首页不需要这么热闹。

我更希望它能简单一点：想看几个视频，就显示几个视频；不想看直播和推广，就把它们过滤掉。

就想着自己写一个脚本。

BiliCompact 就是这么来的。

最开始的目标不复杂：

- 可以自己设置每页显示多少个视频。
- 不想看的直播、广告、番剧和付费内容可以过滤掉。
- 常看的 UP 主可以加入白名单。
- 不需要时可以随时关闭脚本。
- 评论区里一些重复出现的 @ 提及，也希望能顺手清理一下。

这些功能一点点加起来，就成了现在的 BiliCompact。

## 四、它能做些什么

目前脚本主要围绕首页内容筛选和评论区清理两个方向。

### 视频数量与内容过滤

不同页面可以设置不同的视频数量，不必所有页面都使用同一个限制。

例如：

| 页面 | 最大显示数量 |
|---|---:|
| 首页 | 10 |
| 热门 | 8 |
| 分区 | 10 |
| 动态 | 6 |
| 搜索 | 10 |

数量限制之外，还可以选择不显示某些类型的内容：

| 功能 | 说明 |
|---|---|
| 排除直播 | 过滤直播推荐 |
| 排除广告 | 过滤推广内容 |
| 排除番剧 | 过滤番剧推荐 |
| 排除付费课程 | 过滤付费内容 |
| UP 主白名单 | 保留指定 UP 主的视频 |
| 保留推广位 | 设置推广内容是否参与数量限制 |

具体能识别哪些内容，还要看 B 站当前页面提供的元素和信息。

### 评论区清理

评论区也有一个小功能。

脚本可以清理评论中的 @ 提及，根据剩余文字长度决定是否隐藏评论。

例如，去掉 @ 提及后，如果剩余内容不足 5 个字，就可以将这条评论隐藏。

这个功能默认关闭，需要时再从配置面板打开。

### 其他页面元素

脚本还提供了一组可选的页面元素隐藏设置。

包括首页轮播图、频道导航、创作中心入口、直播入口等，共有 13 个可选项目。

如果你希望首页再简单一点，可以按需关闭这些入口，不需要的功能不用全部开启。

## 五、非侵入式的设计哲学

很多同类脚本会在页面注入 UI 元素，按钮、浮窗、侧边栏。好处是交互直观，坏处是**耦合太深**。B 站的前端频繁改版，每次 DOM 结构调整，注入的 UI 就可能错位、失效，甚至阻塞页面渲染。

BiliCompact 的做法相反：

- **不在 B 站页面注入任何 UI 元素**
- 配置面板通过 Tampermonkey 的 `GM_registerMenuCommand` 唤起，以浮层形式展示
- 所有过滤逻辑在后台执行，页面外观无变化

:::fold[details 唤起配置面板的三个入口]
```javascript
GM_registerMenuCommand(T('MenuSettings'), () => OpenConfigPanel());
GM_registerMenuCommand(T('MenuRefresh'), () => LimitVideos());
GM_registerMenuCommand(T('MenuToggle'), () => { IsActive = !IsActive; });
```
:::

这样做的代价是交互入口不那么直观，藏在扩展菜单里。换来的是**高稳定性**：B 站改版几次了，脚本还能正常工作。

## 六、怎么调整设置

BiliCompact 没有在 B 站页面上额外放置一排按钮。

配置入口放在了 Tampermonkey 的菜单中，需要调整时，从扩展菜单打开配置面板就可以了。

这样平时浏览首页时，不会多出一层额外的操作界面。

目前主要设置项如下：

| 设置项 | 作用 | 默认状态 |
|---|---|---|
| 最大显示数量 | 设置每页最多显示多少个视频 | 10 |
| 排除直播 | 隐藏直播推荐 | 开启 |
| 排除广告 | 隐藏推广内容 | 开启 |
| 排除番剧 | 隐藏番剧推荐 | 开启 |
| 排除付费课程 | 隐藏付费内容 | 开启 |
| 保留推广位 | 推广内容不参与数量限制 | 关闭 |
| 调试模式 | 在控制台输出调试信息 | 关闭 |
| 评论净化 | 自动清理 @ 提及 | 关闭 |

不同页面的数量可以独立设置。

脚本还提供了快捷开关，不想使用时可以随时关闭，恢复原来的页面显示方式。

## 七、代码里做了哪些处理

功能本身不算复杂，花时间的地方在让脚本在 B 站不断变化的页面里尽量正常工作。

这里简单介绍几个实现中比较重要的地方。

### 1. 视频卡片怎么找到

B 站页面的 HTML 结构不固定。

如果只依赖某一个 CSS 选择器，页面改版后就可能找不到视频卡片，数量限制也就失效了。

脚本准备了几种查找方式：

- 优先使用已知的视频卡片类名。
- 找不到时，尝试通过其他属性和类名识别。
- 再不行，就从视频链接入手，寻找对应的卡片元素。

简单来说，给查找过程准备了几个备用方案，不把所有希望都寄托在一个选择器上。

:::fold[details 四层兜底各自覆盖多少]
```
第一层  id / class 精准选择器              覆盖 2%
第二层  data-* 属性探测 (data-video-id)     +3%
第三层  宽泛属性选择器 [class*="video"]      +5%
第四层  链接文本回退 (<a href="/video/">)    +80%
----------------------------------------
最终覆盖率                                  99%+
```
:::


脚本会缓存已经找到的选择器，在页面地址发生变化时重新检查，避免 SPA 页面切换后还沿用旧的查找结果。

### 2. 视频是怎么筛选的

找到视频卡片之后，还需要判断哪些应该留下。

目前处理过程大致分为几个步骤：

1. **去重**：避免嵌套元素导致同一个视频被重复计算。
2. **内容过滤**：根据设置排除直播、广告、番剧和付费内容。
3. **白名单检查**：指定 UP 主的内容优先保留。
4. **数量限制**：超过设定数量的视频不再显示。
5. **推广位处理**：根据设置决定推广内容是否占用视频数量。

这样不同规则就不会全部混在一起，后续需要调整时也比较方便。

### 3. 隐藏卡片时遇到的小问题

B 站页面使用了 Grid 等布局方式。

一开始处理页面元素时，要考虑让视频看不见，也要注意隐藏后是否会留下空白。

脚本会对需要隐藏的元素调整显示和布局相关样式，例如 `display`、`height`、`margin`、`padding` 等，尽量避免影响其他卡片的位置。

具体使用哪些样式，要根据元素本身的布局情况决定。

:::fold[details 隐藏一张卡片要同时改九个样式]
```javascript
El.style.display = 'none';
El.style.visibility = 'hidden';
El.style.opacity = '0';
El.style.height = '0';
El.style.margin = '0';
El.style.padding = '0';
El.style.overflow = 'hidden';
El.style.flex = '0 0 0';
El.style.position = 'absolute';
```
:::


### 4. 页面内容会不断变化

B 站首页不是一次加载完所有内容的。

切换页面、滚动加载或者其他动态操作，都可能让新的视频卡片出现在页面上。

如果脚本只在页面打开时运行一次，后面出现的内容就可能漏掉。

BiliCompact 使用了 `MutationObserver` 监听页面变化。

大致过程是：

```text
1. 页面内容发生变化
2. MutationObserver 发现变化
3. 等待或合并频繁触发的更新
4. 重新执行视频筛选
5. 更新页面显示
```

还设置了定时检查，作为动态监听之外的补充。

目前涉及的时间设置包括：

- 200ms 节流，减少高频操作带来的重复执行。
- 300ms 防抖，让部分连续变化的页面操作先稳定下来。
- 5 秒定时检查，处理监听之外可能遗漏的变化。

这些处理主要是为了减少不必要的重复操作，也避免动态加载的视频一直没有经过筛选。

### 5. 评论区的 Shadow DOM

评论净化功能还有一点特殊。

B 站新版评论区使用了 Web Components，其中部分内容放在 Shadow DOM 内部。

普通的页面选择器无法直接访问 Shadow DOM 里面的元素，需要通过 `shadowRoot` 进入对应的开放式 Shadow Root，再寻找评论内容。

:::fold[details Shadow DOM 的层级长什么样]
```
<bili-comments>
  shadowRoot 内
    <bili-comment-thread-renderer>
      shadowRoot 内
        <bili-comment-renderer>
          shadowRoot 内
            <bili-rich-text>
              shadowRoot 内 #contents
```
:::


例如，源码中有这样的处理：

```javascript
function purifierGetContentsEl(renderer) {
    const richText = renderer.shadowRoot.querySelector('bili-rich-text');

    if (richText && richText.shadowRoot) {
        return richText.shadowRoot.getElementById('contents');
    }

    return null;
}
```

找到评论内容后，再处理其中的 @ 提及标签，检查剩余文字长度。

评论区同样是动态加载的，也需要监听变化，让新出现的评论能够得到处理。

### 6. 语言和配置保存

脚本内置了简体中文、繁体中文和英文三种语言。

默认根据浏览器语言选择，也可以在配置面板中手动切换。

语言判断主要通过 `navigator.language` 完成：

```javascript
function ResolveLanguage() {
    if (Config.Language && Config.Language !== 'auto') {
        return Config.Language;
    }

    const Nav = (navigator.language || '').toLowerCase();

    if (/^zh-(tw|hk|mo)$/i.test(Nav) || /^zh-(hant)$/i.test(Nav)) return 'zh_TW';
    if (/^zh/i.test(Nav)) return 'zh_CN';
    if (/^en/i.test(Nav)) return 'en_US';

    return 'zh_CN';
}
```

配置通过 Tampermonkey 提供的 `GM_setValue` 和 `GM_getValue` 保存。

这样刷新页面之后，之前的设置也能继续使用。修改配置后，脚本会根据新的设置重新处理页面，不需要每次都手动刷新。
